# Learned deferral for sanctions entity resolution: classical matchers, LLMs and human review

**Harsh Chauhan, IIT Dharwad. Pattern Recognition and Machine Learning, course project, November 2026.**

Sanctions screening has to decide whether two watch-list records (person, company, vessel, ...) describe the same
real-world entity. On the public **OpenSanctions Pairs** benchmark (755,540 analyst-judged pairs) the published
production scorer reaches 91.3 F1 and frontier LLMs up to 99, and "uncertainty-aware review" is listed as the open problem.

This project asks three questions and answers them on 60k sampled pairs (36k / 6k / 18k train / val / test):

1. **How good is a supervised classical matcher, and how many labels does it need?**
   A random forest over 29 hand-crafted pair features reaches **98.7 F1 (AUC 0.997)** on the 18k test pairs and
   **98.5 F1 on all 375,842 other pairs** of the benchmark (95% CI 98.4 to 98.5), above zero-shot Qwen2.5-7B (95.8),
   Qwen2.5-14B (96.6) and Qwen3-32B (96.8), the best single-threshold rule (94.6) and the production scorer (91.3).
   100 labelled pairs already beat the 7B LLM.
2. **Which pairs should be deferred to an expert, and what does a review budget buy?**
   Treating review as a reject option (Chow 1970): a calibrated-confidence gate lets a human reviewer remove
   **71% of the remaining errors by looking at 5% of pairs** (98.7 to 99.6 F1). Learned gates (error / gain, logistic regression / GBT,
   "learning to defer") do not beat the plain confidence gate. A reviewer who is wrong 10% of the time still reaches 99.25, and the
   same Bayes rule adapts to asymmetric costs (a missed match costing 10x a false match: 10.7% deferred, cost per 1000 pairs 37.9 to 15.6).
3. **Is an LLM a useful expert?** No. From Qwen2.5-7B zero-shot up to Qwen3-32B with chain of thought or thinking mode, deferring
   to the LLM gains at most **+0.25 F1**, and combining it with the matcher instead gains the same +0.2. On the deferred pairs every LLM
   is wrong 18 to 20% of the time against the matcher's own 24%, so there is little to gain, and a ~0.5% hard core of same-name,
   attribute-poor pairs that the analysts judged *different* stays wrong for every system (the thinking model recovers 9 of 89).

Along the way two benchmark artefacts were found and removed: 280,487 auto-generated relational stubs (byte-identical sides, always positive)
and cluster-size count features that leak the label.

## Repository layout

```
notebooks/sanctions_entity_resolution.ipynb   executed notebook: every stage with its outputs and figures under the cells
src/                                          the code the notebook, the paper and the live demo run
  er_lib.py          data sampling (schema filter, de-duplication), split, 34 pair features, record rendering, LLM prompt + vLLM scoring
  er_match.py        seven classifiers (LR, RBF-SVM, kNN, tree, RF, AdaBoost, HGB), 5-fold CV, validation threshold, isotonic calibration
  er_extra.py        rule baselines, learning curve, calibration curve, feature importance, per-type error analysis
  er_gate.py         complementarity, learned gates, deferral curves for human and LLM experts
  er_core.py         the hard core: pairs every system gets wrong
  er_ablate.py       feature-group ablation, count-feature artefact
  er_xtype.py        cross-type generalisation (person / organisation / cross-script)
  er_leakcheck.py    entity-overlap and label-leak checks between splits
  er_strata.py       difficulty strata (easy / medium / hard) and deferral inside the hard stratum
  er_fullpop.py      the sampling-luck check: the trained forest on all 375,842 other pairs
  er_decision.py     noisy reviewer, asymmetric costs (Bayes reject region), combining matcher and LLM instead of deferring
  er_llm32.py        Qwen3-32B as the expert: zero-shot, chain of thought, thinking mode (run32.sh runs the three in sequence)
  er_llm32_eval.py   every expert on the deferred pairs: deferral curves, fixed / broken counts, hard-core recovery
  collect_results.py, make_figs.py, make_notebook.py   results_all.json, every figure, and the notebook itself
  demo.py            live demo (one pair end to end, retrain live, deferral curve, hard core, live LLM call)
results/results_all.json                      all numbers in one file (written by collect_results.py in the notebook run)
results/run_logs.md                           the raw logs of the main runs
figs/                                         paper and slide figures (pdf + png), regenerated by make_figs.py
paper/                                        IEEE double-column paper (main.tex, refs.bib, IEEEtran), compile with pdflatex + bibtex
slides/                                       Beamer slides (slides.tex, 16:9)
setup_env.sh, requirements.txt                environment
```

The `paper/` and `slides/` folders are the exact Overleaf sources.

## Data

OpenSanctions Pairs, file `pairs-20251209.json.gz` (409 MB, CC BY-NC 4.0), from
<https://data.opensanctions.org/contrib/training/pairs-20251209.json.gz>. It is not included in the repository;
`setup_env.sh` downloads it. Derived files (`data/feats.npz`, `data/split.json`, `data/matcher_probs.npz`, the LLM answers
`data/llm_*.jsonl`) are regenerated by the pipeline below and are also not committed.

## Running

The project was developed on the ml.cern.ch JupyterLab service (Python 3.13, one H100 MIG slice for the LLM runs). Everything
except the LLM scoring runs on CPU in a few minutes.

```bash
bash setup_env.sh            # venv with numpy, scikit-learn, rapidfuzz, unidecode, matplotlib, ipykernel + the pairs file
bash setup_env.sh --llm      # additionally vLLM and Qwen2.5-7B-Instruct (GPU only)
```

Paths are configured by two environment variables: `ER_ROOT` (project folder holding `data/` and `figs/`, default `~/prml_proj/er`)
and `ER_RAW` (the pairs file, default `/scratch/hchauhan_prml/pairs-20251209.json.gz`). The main model drops the five
cluster-size count features; set `NOCOUNTS=0` to keep them (that is the ablation).

Full pipeline from the raw file:

```bash
cd src
python er_lib.py sample && python er_lib.py split && python er_lib.py features        # ~3 min
NOCOUNTS=1 python er_match.py                                                          # seven matchers, ~1 min
python er_extra.py
python er_lib.py llm --model Qwen/Qwen2.5-7B-Instruct --which main                    # GPU, ~6 min
python er_lib.py llm --model Qwen/Qwen2.5-14B-Instruct-AWQ --which main               # GPU, ~14 min
python er_lib.py llm --model Qwen/Qwen2.5-7B-Instruct --which main --shots 4          # GPU, ~7 min
NOCOUNTS=1 python er_gate.py rf Qwen2.5-7B-Instruct      # and the two other LLM tags
python er_core.py; python er_ablate.py; python er_xtype.py; python er_leakcheck.py; python er_strata.py
python er_fullpop.py                                                                   # ~2.5 min
python er_decision.py Qwen2.5-7B-Instruct
bash run32.sh                                                                          # GPU, Qwen3-32B zero-shot / CoT / thinking, ~45 min
python er_llm32_eval.py
python collect_results.py && python make_figs.py
```

The notebook runs the same stages in order (it loads the LLM answers from `data/` instead of re-scoring) and was executed
top to bottom with `jupyter nbconvert --execute`; the committed copy keeps all outputs.

Live demo (CPU, seconds):

```bash
python src/demo.py pair --random        # one test pair: records -> features -> P(match) -> gate decision -> LLM answers -> label
python src/demo.py pair --uncertain     # one of the 2% least-confident pairs, i.e. what gets deferred
python src/demo.py train                # retrain the forest live and report test F1 / AUC
python src/demo.py curve                # deferral curves for the human and LLM experts
python src/demo.py core --n 3           # pairs that every system gets wrong
python src/demo.py ask --pid 9212       # live zero-shot answer from Qwen2.5-7B via vLLM (GPU)
```
